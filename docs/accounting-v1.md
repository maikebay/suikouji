# 第一版经营核算与试用说明

2026-10-23。本地 Python/SQLite + 网页实现；用户授权范围：配方单位、月份误入账、平台/渠道、商品品类、费用归属月、每份原料成本和防重复核算。

## 打开与操作

新版正在 http://127.0.0.1:8766 运行，使用 `data/accounting-demo.db`。旧8765服务未停止。新库通过 SQLite backup 复制旧试记库而来，原 `web-demo.db` 未覆盖；迁移前后原始行数量一致，详见 [恢复清单](../data/accounting-migration.json)。新旧库之后分别记录，不自动同步。

重启新版（项目根目录）：

```bash
python3 -m engine.web --port 8766 --db data/accounting-demo.db
```

- 随口记录：`今天买了50斤牛肉花了680`、`今天付了11月房租8000`、`今天美团外卖牛肉面卖了30份，每份12元`。
- 展开“设置商品与配方”：商品名、品类、售价（可空）、产出份数、生效日期、原料用量。`牛肉80克` 与 `牛肉0.08公斤` 等价；一锅10份可填写800克、产出10份。
- “配方成本”：每份原料用量、进价日期、折算单位和每份行成本。示例680元/50斤、80克/份＝2.176元/份，仅牛肉一项。缺任意配方/原料进价或单位无法换算时总成本待补充。
- “销售与月账”：月份筛选，收入/采购付款/费用付款/归属月费用，单品及平台、渠道、品类小计。
- 展开“导入销售或费用CSV”：选择UTF-8 CSV或粘贴内容，预览后确认。网页请求上限32KiB；大文件及Excel用CLI现有导入入口。不会自行读取其他本机路径。

## 字段和口径

Schema v5 在旧表上增列并增加旁路工作空间元数据，保留旧列值、主键、原话和来源链接：

| 对象 | 新增内容 |
| --- | --- |
| entry | platform、channel、period_month、amount_basis、granularity、external_id、source_system |
| sale | platform、channel、product_category、unit、amount_basis、granularity、external_id、source_system |
| product | category |
| recipe_version | product_id、effective_date、配方行JSON；当前 recipe_line 仍保留 |
| import_identity | 店铺、业务身份、内容摘要、导入批次 |
| workspace_meta | 兼容工作空间的 owner、行业 profile、时区 |
| record | context、intent、routing_status、profile_id |

原话、观测、规范词表三层继续存在。财务分析以业务表为准，不能把 observation 的“营业额金额”和“销量金额”跨类型相加。观测可以沿record/ledger_refs回到原始业务行，销售维度不伪装为独立金额观测。

- 采购付款是现金流，不能直接当已售耗料成本。旧 `gross/net/margin/break_even` 不再伪造利润，返回null。
- 标准原料成本＝销售日生效配方每份用量×截至销售日最近采购单价。销售额按明确记录值计算材料毛利，缺金额时可用当前商品标价估算并标记；缺任意金额时完整金额留空。
- 实际耗料成本需要库存计价和真实耗用，本版 `actual_cost=null`。没有做整店净利或租金人工摊到每份的模型。
- `amount_basis=gross` 表示商品销售额，`settlement` 表示已扣费结算实收。不同口径在同日或跨日都不混合求总额；结算口径不算材料毛利。结算实收同时出现平台佣金流水时，收支差额待核对，不再次扣费。
- `period_month` 为YYYY-MM。付款日期独立，例如10月23日付11月房租：10月现金付款，11月归属费用。费用仅按整月归属，不在日查询中自动均摊；日查询里的归属费用明确标为整月。
- 新配方默认今天生效；计算历史销售需显式填历史生效日。不同生效日保留版本，同一生效日重存视为修正该版本。旧配方迁移为未知历史起点的兼容版本，不声称恢复了未记录的历史变化。补记历史采购、修正同日配方会改变相应估算。

## 重复与冲突

- 记错、漏填时在网页「待核对」里补或改，写回原来那一行，不新增账目；每次改动留一条原话和改动前后值。详见 [补充、修正与待核对](review-and-correction.md)。
- 同一消息编号不重复写；不同编号原话都保留。同日同范围的营业总额采用最后录入的一条并提示核对，不视为多笔增量。
- `granularity=transaction` 的收入交易逐笔累加；有明细ID的收入CSV自动采用交易粒度。口语“收款/收入”等记交易，明确“营业额/销售额/总额”等记日总额。
- 没有外部明细ID的销售默认日汇总；同日同范围同商品多个汇总只选最后一条。全店日汇总覆盖平台明细，范围交叉无法判定时完整汇总留空并提示，不凭空补差额。
- 文件哈希防重复文件；跨文件按来源明细ID或日汇总范围去重。商品别名先归一。相同身份内容变化、日汇总与交易明细范围重叠会拒绝整批导入，不覆盖旧数据。原始文件行存在record中。
- 销售交易必须使用唯一订单明细ID，不能拿整单号当每个商品的ID。不同真实交易应有不同ID。
- 无ID流水按规范内容和同表出现序号匹配，保留同文件相同内容的多笔；跨文件完全相同但真实不同的交易无法可靠区分，需提供外部ID。旧批次没有新业务身份时，销售重叠保守拒绝；旧无ID流水不能承诺跨文件自动去重。
- 退款/负销量不取绝对值当正销售，列为待修正。本版不支持完整退款核算。网页遇到无法识别行不允许确认导入；CLI会展示跳过行后接受用户明确`--commit`。

销售CSV字段示例：

```csv
日期,平台,渠道,商品品类,商品,数量,销售额,数据粒度
2026-10-23,美团,配送,面食,牛肉面,30,360,日汇总
```

费用CSV：

```csv
日期,类型,分类,金额,费用归属月份
2026-10-23,支出,房租,8000,2026-11
```

CLI新增选项：`product --category`；`recipe --units --category --effective-date`；`sale --platform --channel --category --amount-basis --granularity`。`add-json` 接受归属月和同类字段。默认不推断平台意味着配送，渠道可以留空；“外卖”归一为配送。

## 实测与边界

- `python3 -m unittest discover -s tests`：149项通过。新增测试见 [核算回归](../tests/test_accounting.py)、[HTTP回归](../tests/test_web.py)。旧v1迁移用冻结DDL，v2临时库检查旧列值、重开幂等，高版本拒绝不改表。
- 实际CLI经过采购、跨月房租、配方、平台销量、成本和月报，均退出0；实际300元收入/30份，标准耗料65.28元，材料毛利估算234.72元。
- 浏览器实际保存“验收牛肉面”配方、预览并确认CSV：30份/360元、标准成本65.28元，与已有1280元营业总额不相加。验收示例留在独立新试记库。375px页面无横向溢出，控制台无错误。
- 自然语言仍是有限规则；任意口语、非法日期和复杂多月费用不保证正确，应核对原始明细。无单位/同名歧义不猜进价。支持重量及体积同族换算，瓶/箱/袋不能自动换算重量。
- 未验收真实平台导出、微信实际接入、CloudBase同步、公网部署、退款、盘点计价、净料出成率、多SKU规格及季度/年度费用自动分摊。
