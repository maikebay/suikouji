# 生意随想首版：0.2.0-staging 验收记录

日期：2026-10-26。本次在本地目录实施，目录不是 Git checkout；没有创建分支、提交、PR或发布 GitHub。所有数据库测试使用内存库或临时目录，未读取或修改现有账本、账号凭据与线上环境。

## 已实现范围

- 独立 `thoughts` 与有索引的 `thought_tags`，经同工作空间 `capture_id` 关联原话，不使用账目引用，不参与财务核算。
- `POST /v1/captures` 支持可选 `structured.thoughts`。四个旧数组仍必填；新请求验证副本补随想空数组，不改变原始请求指纹。原话、各领域投影、标签、请求认领与完整回执同事务提交。
- 随想只保存记事正文、归档日、可选标题/标签和逐字来源。不接受 assertion、计划类型、任务状态、提醒时间或金额字段。
- `GET /v1/thoughts` 支持记录日期闭区间、重复 tag 的 AND 筛选、标题/正文关键词和稳定分页。游标绑定工作空间与筛选条件。
- 原话详情包含完整随想；时间线保留一条原话一个条目，增加随想计数、最多三条预览及 `types=thought` 筛选。
- 原生录入支持明确随想标记和文档列明的有限句首表达，先隔离随想内部的日期、金额与数量，再处理账目。正文里的明天、下周不创建任务，也不改随想归档日。
- 对列明的近似金额保留未解析片段；中文 CLI 与 iLink Bot 回执区分实际保存的账目、随想及未入账内容。没有标签不追问。
- schema v6；显式 `engine.deployment migrate SOURCE DESTINATION` 只读旧 v5 库并生成新的迁移副本。认证 API、旧本地网页接口和 Bot 的运行连接均拒绝隐式迁移；本地试用只允许启动前初始化不存在的新路径。SQLite 备份/恢复检查新增表、索引与归属约束，工作空间导出覆盖新增表。
- 能力契约、完整结构化示例、OpenAPI、解析边界、部署升级和外部 Agent 安装介绍已同步。

## 独立审查与补充回归

审查在已有测试通过后继续检查近似金额、随想片段隔离、日期继承、历史重复请求、查询与升级。已复现的问题包括：

- 旧本地网页数据接口可能隐式升级旧库；运行连接现使用严格模式，旧库请求返回503，源文件不变。
- 备份检查只看版本号时可能接纳缺表/索引的v6库；检查现覆盖完整运行schema，拒绝发布不完整备份或恢复副本。
- 原生近似金额跨行、设想售价、跨随想拼接、外层日期继承、明确客流/天气、英文句号及重复请求profile等边界已修复。追加组合回归覆盖日期独占一行、实际金额后紧跟预算/设想、观测单位后的近似后缀及销量付款冲突时的逐字来源还原；162项相关套件通过。
- 时间线损坏游标原先可能静默漏页/重页，现返回400；原有效三元组格式保留。
- 无效Unicode原先可能在请求指纹阶段返回500，现原样检查并返回400，不改变合法请求的指纹。随想文本的U+0000存储约束已纳入字段契约，回归检查拒绝且无半写入。

最终四项组合修复另经独立只读复核：指定四项及相关103项测试通过，未发现这些修复中的具体缺陷。接口修复的独立复核也确认旧指纹/缓存不变，12条不同日期时间格式的时间线记录分页无重漏。上述独立复核范围有限，不替代全量和实际HTTP验收。

一次游标异常字符的独立验证被模型服务拦截，部分扩展Unicode探针因自动审批分类服务不可用未执行。它们不计入独立实测证据；主线程完成了普通无效Unicode日期、损坏时间线游标与既有缓存兼容的入口回归，游标共享校验覆盖UTF-8可编码性。

## 升级与适用边界

旧 v5 库须先用旧版工具备份，按 [部署升级步骤](../deploy/README.md#从-v5-升级到-v6) 演练副本迁移；真正切换前停写、生成最终备份并迁移最终副本。回退需旧程序与匹配的旧备份，不能只回退镜像。本文的测试没有执行用户环境的迁移或切换。

没有验收 Docker build/run、GitHub clone 安装、真实服务器、真实腾讯 iLink Bot 或外部 Grokbot 的对话行为。字符串测试仅证明产品自身模板与机器契约，不能证明任意外部 Agent 都遵守政策。

原生 iLink 仍是受控规则入口，没有模型、自动欢迎、查询对话或多轮确认状态机。首版仍受 restaurant profile 限制；其他行业不能用纯随想绕过确认边界。没有新增随想编辑/删除、定时任务、库存/剩料核算、固定报表或完整 Web 随想界面。
